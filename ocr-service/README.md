# ocr-service

Тупой (dumb) OCR-сервис: изображение бирки на вход -> распознанные строки
текста на выход. Никакой бизнес-логики (парсинг полей заказа/детали,
сопоставление со справочниками и т.п.) — это ответственность backend.
Сервис не хранит состояние и не требует авторизации; предназначен для
внутренней сети (вызывается backend-ом, не выставляется наружу напрямую).

## Стек

- FastAPI + Uvicorn
- RapidOCR (модель PP-OCRv5, вариант `eslav` — кириллица/латиница, mobile-модель)
- OpenCV (headless) для декодирования изображений и даунскейла

## API

### `GET /health`

```json
{ "status": "ok", "model": "PP-OCRv5-eslav" }
```

### `POST /ocr`

Тело запроса — **сырые байты изображения** (`Content-Type: application/octet-stream`).
Multipart/form-data не поддерживается — это сознательно уменьшенная
поверхность API.

Поддерживаемые форматы изображений: любые, которые декодирует OpenCV
(`cv2.imdecode`) — как минимум PNG, JPEG, BMP (включая 1-бит BMP, как в
исходных `.emf`-бирках Bazis).

Ограничение размера тела: 10 МБ. Проверяется по заголовку `Content-Length`
до чтения тела (мгновенный ранний отказ), а также потоково по мере чтения
(на случай отсутствующего/неверного `Content-Length`).

Успешный ответ (200):

```json
{
  "lines": [
    { "text": "2590", "score": 0.98, "box": [[x, y], [x, y], [x, y], [x, y]] }
  ],
  "durationMs": 123
}
```

Дополнительный лимит размерностей (image-bomb guard): ширина/высота
считываются из заголовка файла (PNG IHDR / BMP header / JPEG SOF) **до**
декодирования пикселей; при стороне > 12000px или площади > 40 Мп — `400`
с detail `image dimensions too large`. Так маленький по байтам, но огромный
по пикселям файл не раздувает память на этапе декода.

Коды ошибок:

- `400` — тело пустое, не является читаемым изображением или объявляет
  чрезмерные размерности изображения.
- `413` — тело больше 10 МБ.
- `429` — сервис занят: одновременно обрабатывается не более одного запроса
  (модель не потокобезопасна для параллельного инференса), очередь ожидания
  ограничена тремя запросами. Клиент должен повторить запрос позже.

## Backpressure

Инференс выполняется под `asyncio.Semaphore(1)` в отдельном потоке
(`asyncio.to_thread`), чтобы не блокировать event loop. Если запросов,
ожидающих освобождения семафора, уже 3 — новый запрос получает `429`
немедленно, не вставая в очередь.

## Модель и офлайн-работа

Модели RapidOCR (PP-OCRv5, `eslav`, mobile) скачиваются и запекаются в
Docker-образ на этапе `docker build` (прогрев движка вызывает загрузку onnx
в `site-packages/rapidocr/models`). Билд требует сети; рантайм — нет.
Проверено запуском тестов с `--network none`.

## Локальная разработка

```bash
docker build -t erp-ocr-service:dev ocr-service/
docker run --rm -p 8000:8000 erp-ocr-service:dev
```

Тесты внутри контейнера:

```bash
docker run --rm erp-ocr-service:dev python -m pytest tests/ -v
```
