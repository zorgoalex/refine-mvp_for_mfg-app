# WhatsApp-рассылки (несколько рассылок, этап A)

Заменяет единственную «ежедневную рассылку заказов» (`whatsapp-daily-digest.md`).
Миграция `209_whatsapp_broadcasts.sql` переносит прежние настройки в рассылку №1.

## Что умеет рассылка

- Своё название, группа WhatsApp, **дни недели** (Пн–Вс), начало окна отправки и
  случайное окно, политика догона и контрольное время, политика частичной отправки.
- **«Заказы на»**: сегодня, завтра или через N дней (0–14) — берутся производственные
  заказы с плановой датой сдачи на эту дату. Нет заказов — ничего не отправляется
  (запуск `empty`).
- Карточки заказов (1 или 2 на картинке) и **подпись к первой картинке** — шаблон с
  переменными `{current_date}`, `{current_time}`, `{weekday}`, `{target_date}`,
  `{target_weekday}`; для фигурных скобок — `{{` и `}}`.
- Одновременно включено не больше 20 рассылок.

Текстовые сообщения по шаблону, счётчики, списки заказов, фильтры по справочникам и
остатки — следующие этапы (B/C).

## Расписание

- Раз в 15 секунд backend **фиксирует** слот дня для каждой включённой рассылки, у
  которой сегодня рабочий день недели: выбирает минуту внутри окна (один раз на день и
  поколение расписания) и, когда минута наступила, создаёт автоматический запуск.
  Решение «окно пропущено» принимается в этот момент.
- Раз в 30 секунд — **доставка** готовых сообщений (не больше 20 за проход, по очереди
  между рассылками), затем **подготовка** картинок (не больше двух запусков за проход).
- Дедлайн доставки: контрольное время (`until_deadline`), конец дня (`end_of_day`) или
  зафиксированная минута + 30 минут (`skip`).
- Изменения времени, окна и догона после фиксации действуют с завтрашнего дня.
  **«Перепланировать сегодня»** применяет их сразу, пока сегодняшняя отправка не
  началась: прежний запуск помечается вытесненным (история сохраняется), минута
  выбирается заново. Если хоть одно сообщение уже отправляется или отправлено —
  отказ `BROADCAST_TODAY_ALREADY_SENDING`.
- Изменение настроек во время подготовки (группа, число карточек и т. п.) вытесняет
  подготовку; на следующем проходе запуск фиксируется заново с новыми настройками.

## Права

Все операции требуют `whatsapp.manage`, `calendar.view`, `orders.view`,
`orders.view_financials`. Автоматический запуск выполняется от имени того, кто последним
сохранил рассылку; перед каждой отправкой проверяется, что этот пользователь активен и
имеет все права. Для ручной отправки и повтора проверяются автор исходного снимка и
инициатор. Если права отозваны — запуск `failed` `BROADCAST_AUTHOR_PERMISSION_REVOKED`.

## Пауза «Остановить все рассылки»

`POST /api/v1/whatsapp/broadcasts/control {version, paused: true}`: пока включена пауза,
не создаются ни команды (ручная отправка, повтор, перепланирование), ни автоматические
запуски, ни новые попытки отправки. Уже начатая отправка сообщения завершается.

## Идемпотентность

Ручная отправка, повтор и перепланирование принимают `idempotencyKey`. Ключ
уникален в пределах рассылки: повтор с тем же ключом и теми же параметрами
возвращает прежний результат, с другими — `409 IDEMPOTENCY_KEY_REUSED`.

## Хранение

Картинки — в `<WHATSAPP_DAILY_DIGEST_DIR>/broadcasts/`, срок 23 ч 50 мин. Снимки
заказов очищаются через 30 дней, история запусков и журнал команд — через 90 дней.
Backend продолжает очищать таблицы и картинки прежней рассылки по старым срокам;
её история доступна только для чтения (`GET /broadcasts/legacy-digest-runs`).

## Переключение на production (runbook)

1. Выкладывать вне окна отправки. В старом интерфейсе убедиться, что в истории нет
   запусков в очереди или в отправке (при необходимости дождаться доставки).
2. Остановить старый backend: `compose stop backend`.
3. Проверить:
   `SELECT count(*) FROM whatsapp_daily_digest_runs WHERE state IN ('queued','sending');`
   `SELECT count(*) FROM whatsapp_daily_digest_pages WHERE state IN ('pending','sending');`
   — оба 0.
4. Применить миграции (`ops/apply-migrations.sh`). Миграция 209 повторяет проверку и при
   незавершённой очереди прерывается без изменений (`WHATSAPP_DIGEST_QUEUE_NOT_DRAINED`).
   В одной транзакции она создаёт рассылку №1 из прежних настроек и выключает прежнюю
   рассылку (аудит `whatsapp.daily_digest.settings.disabled_by_cutover`).
5. Запустить новый backend. Если прежняя рассылка уже отправила сегодня, №1 сегодня
   не отправит (проверка по старой истории).

Frontend определяет версию backend сам: при `404` на `GET /whatsapp/broadcasts`
показывает прежний экран, иначе — новый. Порядок выкладки frontend/backend не важен.

## Откат на предыдущий backend

1. Включить паузу «Остановить все рассылки» в интерфейсе. Если интерфейс недоступен —
   одной транзакцией, с атрибуцией и аудитом (подставить ID пользователя, выполняющего
   откат, и дату):
   ```sql
   BEGIN;
   UPDATE whatsapp_broadcast_control
     SET paused = true, version = version + 1, paused_at = now(), paused_by = <user_id>, updated_at = now()
     WHERE singleton_id = 1 AND NOT paused;
   INSERT INTO audit_log (event, entity_type, entity_id, user_id, request_id, source, before_json, after_json)
     VALUES ('whatsapp.broadcast.control.paused', 'whatsapp_broadcast_control', '1', <user_id>,
       'rollback-<YYYY-MM-DD>', 'runbook', '{"paused": false}', '{"paused": true}');
   COMMIT;
   ```
2. Дождаться, пока нет сообщений в отправке:
   `SELECT count(*) FROM whatsapp_broadcast_messages WHERE state = 'sending' OR (state = 'pending' AND lock_token IS NOT NULL);` — 0.
3. Остановить новый backend (`compose stop backend`) и убедиться, что контейнер остановлен.
4. Очистить содержимое новых таблиц и завершить незаконченную работу (очистка
   терминальна: вернувшийся новый backend такие запуски не готовит и не отправляет):
   ```sql
   BEGIN;
   UPDATE whatsapp_broadcast_messages SET state = 'cancelled', error_code = 'CONTENT_PURGED', updated_at = now()
     WHERE state = 'pending';
   UPDATE whatsapp_broadcast_runs SET state = 'cancelled', reason = 'CONTENT_PURGED', updated_at = now()
     WHERE state IN ('preparing', 'queued', 'sending');
   UPDATE whatsapp_broadcast_runs SET snapshot = NULL, content_purged_at = now() WHERE content_purged_at IS NULL;
   UPDATE whatsapp_broadcast_messages SET caption = NULL, text_body = NULL;
   COMMIT;
   ```
   и удалить каталог `<WHATSAPP_DAILY_DIGEST_DIR>/broadcasts/`.
5. Запустить предыдущий образ backend. Прежняя рассылка выключена (это сделала миграция):
   включить её в старом интерфейсе, когда нужно (если рассылка №1 уже отправила сегодня —
   с завтрашнего дня). Её настройки — на момент переключения.

Миграция не откатывается; новые таблицы старым backend не используются.
