# Отправка заказа в WhatsApp из карточки заказа

В меню «⋯» карточки заказа есть две команды:
- «Отправить клиенту в WhatsApp» — на личный номер клиента заказа;
- «Отправить в чат «…»» — по одной команде на каждый чат из настроек.

В подменю выбирается форма заказа. Отправка начинается сразу, без подтверждения.

Модуль: `backend/src/modules/whatsapp/order-send/`. Миграция: `230_whatsapp_order_send.sql`.

## Формы

Реестр форм — `order-send.types.ts` (`ORDER_FORMS`). Файл собирает backend из данных заказа; браузер
файлы не передаёт.

| Код | Название | Файл | Цены |
|---|---|---|---|
| `production_pdf` | PDF для производства | PDF | нет |
| `order_pdf` | PDF заказа | PDF | да |
| `production_excel` | Excel для производства | XLSX | нет |
| `order_excel` | Excel заказа | XLSX | да |

- **Excel** собирает тот же построитель, что и кнопка Excel в карточке
  (`src/utils/excel/orderExcelBuilder.ts`), на том же шаблоне.
  - Backend хранит точные копии построителя (`forms/shared/`) и шаблона
    (`backend/assets/order-forms/order_template.xlsx`).
  - Тест `shared-copy.test.ts` сверяет копии побайтно.
  - После правки исходника скопируйте файл заново.
- **PDF** рисует pdfkit (`forms/pdf-form.ts`) раскладкой бланка заказа. Шрифты — Liberation Sans из
  `backend/assets/fonts`. «Для производства» группирует детали по плёнке.
- **Формы без цен** получают проекцию без цен, сумм, скидки, платежей и остатка, даже если
  отправитель видит финансы. В Excel режим без цен не пишет платежи (O–Q).
- **Новая форма** = запись в `ORDER_FORMS` + генератор в `forms/index.ts` + расширение CHECK кодов
  форм в миграции.

## Настройки

Конфигурация → «Рассылка сообщений» → «Отправка заказа из карточки». Право `whatsapp.manage`.

| Настройка | Значение |
|---|---|
| Включено | По умолчанию выключено. |
| Порог частоты | 1–1440 минут, по умолчанию 1. Общий на всю систему: начала доставок из карточек — не чаще раза в N минут. |
| Окно отправки | 0 … половина порога, минуты (по умолчанию 0). Следующая доставка уходит в случайный момент окна после порога: при пороге 10 и окне 5 — через 10–15 минут после предыдущей. Случайная задержка выбирается один раз в момент доставки (`next_delivery_at`), смена порога или окна перевыбирает её от последней доставки. |
| Клиенту | Разрешённые формы и шаблон подписи. Пустой список — пункт клиенту не показывается. |
| Чаты | До 20 чатов. У каждого: группа, название в меню, формы, подпись. |

Ключ чата (`chatKey`) живёт, пока не меняется группа. Смена группы или удаление чата архивирует строку
(`archived_at`) и отменяет поставленную в очередь отправку в неё (`recipient_removed`). Новая группа
получает новый ключ. Строки чатов не удаляются: группа неизменяема (триггер), история ссылается на ключ.

Выключение отменяет отправку, стоящую в очереди (`disabled`).

Переменные подписи: `{order_name}`, `{client}`, `{order_date}`, `{completion_date}`, `{form}`.

## Права

| Действие | Права |
|---|---|
| Меню и отправка | `orders.view` и `orders.export`, каждое в своём scope (`all` / `own` / `assigned`) |
| Формы с ценами | дополнительно `orders.view_financials` |
| Настройки | `whatsapp.manage` |

Меню (`GET /whatsapp/order-send/menu`) не содержит ID групп, а формы с ценами в нём показываются только
пользователю с финансами.

## Команда `POST /api/v1/orders/:orderId/whatsapp-sends`

1. Доступ к заказу (view + export в scope).
2. Журнал идемпотентности (`actor_id`, `idempotency_key`):
   - тот же ключ с тем же заказом, получателем и формой → прежний ответ, даже если с тех пор
     выключили отправку, сменили телефон или WhatsApp недоступен;
   - другое тело → `IDEMPOTENCY_KEY_REUSED`.
3. Транзакция:
   - блокировки `whatsapp_broadcast_control` FOR SHARE → настройки FOR UPDATE;
   - журнал ещё раз;
   - проверки: пауза, включено, нет активной отправки (`ORDER_SEND_ACTIVE`), порог
     (`ORDER_SEND_COOLDOWN` с `nextAllowedAt`), чат, разрешённая форма, финансы, телефон;
   - чтение заказа FOR SHARE, сборка файла, запись в хранилище, строка `queued`, аудит `requested`.
4. **Повтор после неизвестного результата.** Если последняя отправка того же заказа тому же
   получателю той же формой закончилась `unknown`, команда отказывает `ORDER_SEND_PREVIOUS_UNKNOWN`
   (`details.sendId`). Повтор проходит только с `confirmAfterUnknown` = этот `sendId` — карточка
   спрашивает «Отправить ещё раз?». Проверка идёт под блокировкой настроек, поэтому вкладки
   браузера не могут её обойти.
5. Отказ пишет отдельную строку аудита `whatsapp.order_send.refused` и техническую запись. Телефона и
   ID группы в них нет.

## Телефон клиента

- **Выбор номера** — как в экспорте заказа: основной номер клиента, иначе наименьший.
- **Разбор номера** (`order-send-phone.ts`):
  - основной номер выделяется до удаления форматирования;
  - добавочный или второй номер после разделителя (`-`, `,`, `;`, `/`, «доб.», «вн.») отбрасывается;
  - результат — `7XXXXXXXXXX`;
  - всё остальное — `CLIENT_PHONE_INVALID`.
- **Chat id** (`@c.us` или `@lid`) worker узнаёт через WAHA `check-exists` прямо перед отправкой.
  Номера нет в WhatsApp — `failed / CLIENT_NOT_ON_WHATSAPP`, порог не тратится.
- **Где виден телефон.** В аудите, журнале и ответах API — только маска `7701***2060`. Технический
  журнал WAHA пишет путь без query.

## Доставка (worker)

Не больше одной активной отправки на систему. Worker работает только при `relayOwner=in_process`; шаг
— раз в 15 секунд и сразу после команды.

Перед отправкой, под блокировкой настроек, worker перепроверяет:
- текущие права отправителя (view, export, финансы — по ролям из БД);
- что чат на месте, его группа совпадает с сохранённой, а форма разрешена;
- для клиента — что форма разрешена, заказ у того же клиента, а выбранный телефон тот же.

Любое расхождение → `cancelled` с причиной. Отправка никогда не перенаправляется.

Порог доставки (delivery gate):
- если `now` раньше `max(last_delivery_at + порог, next_delivery_at)`, отправка ждёт (`next_attempt_at`);
- иначе `last_delivery_at = now`, `next_delivery_at = now + порог + random(0..окно)` — слот тратится в
  начале попытки и не возвращается.

Команда отказывает `ORDER_SEND_COOLDOWN` только до конца порога. Отправка, поставленная внутри окна,
ждёт выбранного момента в очереди. Если окно уже прошло, она уходит сразу.

Итог попытки (`sendFile`):

| Результат | Состояние |
|---|---|
| ответ с непустым id сообщения | `sent` |
| ответ без id, таймаут, 5xx | `unknown`, без повтора |
| явный отказ WAHA (400, 404, 405, 415, 422, 501) | `failed` (`WAHA_REJECTED` / `WAHA_FILE_UNSUPPORTED`) |

Fallback на картинки нет.

Восстановление и очередь:
- строка `sending` старше `BACKEND_WHATSAPP_RELAY_STALE_LOCK_MS` → `unknown` (`PROCESS_LOST_AFTER_INTENT`);
- «Остановить все рассылки» останавливает и эти отправки: строка ждёт;
- очередь живёт 30 минут, считая от момента, когда отправку можно доставить (`max(сейчас, порог/выбранный момент окна) + 30 мин`), затем `expired`; смена порога или окна будит ожидающую отправку и при необходимости продлевает срок.

## Хранение

- Файлы лежат в `<WHATSAPP_DAILY_DIGEST_DIR>/order-sends/` (своя блокировка): 10 МиБ на файл,
  512 МиБ на каталог. При заполнении — `ORDER_SEND_STORAGE_FULL`.
- Через 7 дней у завершённых отправок удаляются файл, ID группы, телефон и `provider_message_id`
  (в нём бывает номер). Остаются статус, маска и `provider_ack`.
- Файлы без ссылки старше часа (откат команды после сбоя) удаляются при очистке.

## Выкладка и откат

- **Миграция 230 аддитивная.** Старый backend новых таблиц не читает, переключение со стопом не
  нужно: сначала миграция, затем новый backend. Функция выключена, пока администратор её не включит.
- **Проверка до включения на production:** пробная отправка PDF и XLSX в тестовую группу и на свой
  номер. Это проверяет `sendFile` установленной WAHA.
- **Откат:** выключить отправку в настройках (отменит очередь). После отката backend строки `queued`
  истекут по сроку очереди, а строка `sending` после возврата станет `unknown`.

## «Мои отправки»: балуны и время под колокольчиком

`GET /api/v1/whatsapp/my-sends` отдаёт отправки текущего пользователя за последние 24 часа (до 30):
- из карточки — по `actor_id`;
- из календаря — по `initiated_by_user_id`.

Отдельного права не нужно: видны только свои отправки. ID групп и телефоны в ответ не попадают,
только заголовок вида «Заказ 230725 → клиенту, PDF заказа».

`estimatedAt` — примерное начало доставки для ожидающих отправок:
- карточка — `max(сейчас, next_attempt_at, max(порог, выбранный момент окна))`;
- календарь — `max(сейчас, ближайшее сообщение, порог календаря до начала доставки)`.

Frontend (`src/components/whatsapp/`):
- колокольчик опрашивает `my-sends` каждые 15 с, пока есть ожидающие отправки; в течение 30 минут
  после активности — раз в минуту; иначе только по сигналу «поставлено в очередь» из карточки или
  календаря;
- завершение отправки, которую видели ожидающей, показывает полупрозрачный балун внизу справа на
  15 с с крестиком;
- ожидающие отправки показываются блоком «WhatsApp: ожидают отправки» в выпадающем списке
  колокольчика.
