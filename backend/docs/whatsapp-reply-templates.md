# Шаблоны личных ответов WhatsApp

Функция относится к личным автоответам, не к групповым входящим сигналам и не меняет статусы заказов.

## Пример

1. В «WhatsApp-правила → Сообщения» создайте ответ, формат **Шаблон с переменными**:
   `Заказ №{order_number} принят. {current_date}, {current_time}. Обращение №{counter}`.
2. В «Ключевые слова» создайте правило, выберите ответ и совпадение **По шаблону: сообщение целиком**.
3. Входящий шаблон: `Заказ {order_number:number} готов`.
4. В «Проверить на примере» введите `ЗАКАЗ 002222 готов`. Должно извлечься `order_number = 002222`.
5. Выберите «Обычное сообщение» либо «Ответ с цитатой исходного сообщения», сохраните правило.

Каждый вариант входящего шаблона вводится на отдельной строке. Запятые в нём остаются частью текста.
Старые ключевые слова по-прежнему разделяются запятой либо новой строкой.

## Синтаксис

- `{name:number}`: цифры 0–9, сохраняются ведущие нули.
- `{name:word}`: буквы, цифры, подчёркивание и дефис без пробелов.
- `{name:text}`: непустой текст из одного или нескольких слов.
- Между соседними полями обязателен фиксированный текст или пробел. Максимум 8 полей, имена уникальны, строчная латиница/цифры/подчёркивание, начало — буква.
- Регистр фиксированного текста не важен. Повторные пробелы/переносы строк в новых шаблонах считаются одним пробелом.
- Захват максимально длинный, при котором остаток шаблона совпадает; альтернативы проверяются сверху вниз. Сложные неоднозначные шаблоны ограничены по вычислениям и завершаются понятной ошибкой. Это не произвольные регулярные выражения.
- Номер извлекается из текста, наличие заказа в ERP не проверяется.

В ответе `{name}` вставляет извлечённое значение один раз, без рекурсивного исполнения. `{current_date}` — ДД.ММ.ГГГГ, `{current_time}` — ЧЧ:ММ, часовой пояс Asia/Almaty. `{counter}` — отдельная непрерывная нумерация для правила; начинается с 1, без сброса. Для буквальных скобок в режиме шаблона: `{{` и `}}`. Режим **Обычный текст** ничего не подставляет, старые сообщения сохраняют этот режим.

Все варианты входящего шаблона должны предоставлять переменные выбранного ответа. Проверка действует при сохранении и правила, и ответа, включая связанные отключённые правила. Чтобы поменять несовместимые поля в общем ответе, создайте новый ответ и переназначьте правила.

## Отправка и диагностика

Предпросмотр проверяет только редактируемое правило, не конкуренцию приоритетов. Он не пишет в БД, не отправляет сообщение и показывает условный счётчик 1.

На входящем сообщении срабатывает первое активное подходящее правило по приоритету и ID. Готовые текст, время, счётчик и способ цитирования фиксируются в задании. Повтор webhook не создаёт ответ и не расходует номер. Повтор отправки не пересчитывает текст. Пропуски нумерации возможны при окончательно неудачной доставке; это не бухгалтерская нумерация.

Если сформировать ответ нельзя, задание получает «Ошибка» и безопасный код причины. Исправьте правило/ответ и отправьте новое сообщение: существующий снимок не переформируется. При ошибке цитирования обычный ответ автоматически не отправляется. Если результат вызова WAHA неоднозначен, сохраняется прежняя политика `unknown`, без автоматического дубля.

WAHA `POST /api/sendText` получает исходный `payload.id` в `reply_to`; хеш для дедупликации отдельно. [Контракт WAHA](https://waha.devlike.pro/docs/how-to/send-messages/#reply-on-message). Сырой ID цитаты не выводится в аудит/технический журнал и очищается вместе с текстом завершённого задания по прежнему TTL.

## Развёртывание и проверки

Перед новым backend применить `176_whatsapp_reply_templates.sql`. Старые правила и задания остаются обычными; никакие relay-флаги миграция не включает. При откате кода сначала отключить новые pattern-правила/шаблоны и остановить relay: старый backend не понимает новые режимы. Не удалять очередь и колонки при откате.

`WHATSAPP_REPLIES_DOCKER_TEST=true npx vitest run backend/src/modules/whatsapp --maxWorkers=1` проверяет реальный PostgreSQL в отдельной временной схеме. На shared host обязательно запускать через ресурсный guard проекта. Live цитирование требует подключённого WAHA и отдельного контрольного сообщения с другого номера.
