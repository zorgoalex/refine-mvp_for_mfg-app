# Товары и услуги

Самостоятельный справочник продаваемых позиций, не производственных деталей.

## Работа в приложении

1. Откройте **Данные → Товары и услуги** (в старом меню — **Справочники**).
2. Нажмите **Создать позицию**. Заполните название, тип и единицу измерения.
3. Артикул, базовая цена и описание необязательны. Артикул уникален без учёта регистра, включая архив. Пустая цена означает «не задана», `0` — нулевую цену. Валюта — KZT.
4. Сохраните. Для изменения откройте **Изменить**; выключите **Активна**, чтобы архивировать. Для восстановления выберите фильтр **Архив**, откройте карточку и включите активность.

Физического удаления нет. Цена справочная: сохранение не меняет существующие заказы и платежи. На этом этапе нет сопоставления или импорта строк Bitrix. Детали производства и правила конвертации CRM-заявки не изменены.

Просмотр: `references.view` или `references.manage`. Изменения: `references.manage`, активный пользователь ERP (не service account). Название роли само по себе права не даёт.

При конфликте версии форма сохраняет введённое; **Загрузить версию** заменит черновик только после подтверждения. При неизвестном результате сетевого запроса поля блокируются: **Проверить повтором** повторяет ту же команду с тем же ключом. Не открывайте вторую форму для повторного создания той же позиции.

## API и хранение

`GET /api/v1/catalog-items`, `/units`, `/:id`; `POST /api/v1/catalog-items`; `PUT /api/v1/catalog-items/:id`. Полная схема — `backend/contracts/04-api-contract.openapi.yaml`.

Команды требуют `Idempotency-Key`, изменения — также `expectedVersion`. Идентичный повтор возвращает сохранённый ответ. Другой actor/ID/body с прежним ключом —409. Успешная команда, аудит и outbox атомарны; no-op не меняет версию и не добавляет бизнес-событие. Поля каталога не пишутся через Hasura.

`catalog_items` хранит позиции; `catalog_item_commands` — подтверждения выполненных команд. Подтверждения пока хранятся бессрочно, чтобы не создавать дубли поздними повторами; API для их просмотра/очистки нет. События `catalog.item_created|updated|archived|restored` пишутся в аудит и общий outbox. Новых отправителей уведомлений/правил не добавлено.

## Обновление окружения

1. Проверить точный commit, pending-список миграций и отсутствие чужих изменений. Новая миграция: `157_products_services_catalog.sql`.
2. Через существующий `ops/apply-migrations.sh` применить миграцию и проверить её end-state probe. Она добавляет две таблицы и индексы, не заполняет каталог примерами и не меняет `units`.
3. Собрать backend с новым SHA, обновить существующий сервис backend обычным Compose окружения; дополнительные Compose-файлы или переменные не нужны.
4. Дождаться frontend того же SHA. Проверить health/live, health/ready, затем список единиц/позиций и создание→изменение→архив→восстановление тестовой позиции.
5. Проверить чтение без прав и запрет сохранения с правом только просмотра. В production не создавать тестовые оплаты/заказы ради проверки каталога.

Rollback: вернуть прежние образы backend/frontend. Additive-таблицы оставить; destructive down-миграции нет. Production обновляется только после отдельного разрешения.
